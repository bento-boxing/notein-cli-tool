# `notes` CLI — design

Date: 2026-11-14

## Intent

The user takes handwritten university notes in the Notein tablet app, which backs
them up to Google Drive in its own `.in` format. She wants one terminal tool
that pulls that backup, files the useful notes into a clean per-module folder
tree as PDFs, and then starts Claude Code sessions that turn a module's
material into Anki flashcards and practice exams for revision.

## Goals

- One Python CLI, `notes`, covering sync, organise, convert, flashcards, exams.
- Safe to re-run at any time: only new or changed notes are processed.
- Flashcards import into Anki with one click and re-import without duplicates.
- Adding next year's modules is a config edit, not a code change.

## Non-goals

- No two-way sync. Nothing is ever written to Google Drive.
- No calls to the Claude API. Flashcards and exams are produced by launching
  the user's own `claude` CLI with a prepared prompt.
- No handling of Revision (`Rev`), practice exam (`PE`), coursework (`CW`),
  textbook or question-sheet notes. They are skipped.
- No separate OCR step or OCR software in the tool. The handwriting is read
  by Claude itself: in the launched session it opens each PDF page as an
  image and reads the handwriting directly. The PDFs therefore only need to
  be clear and legible, not searchable.

## Anti-goals

- Modifying or deleting anything in `NoteInDataSync`, `Notein`, or any
  `Lecture-Slides` folder.
- Silently dropping a note. Every note is either converted or listed as
  skipped with a reason.

## Layout

```
/home/user/Documents/NoteinNotes/
├── data/
│   ├── NoteInDataSync/        rclone target, read-only to the tool (423 notes + folder entries)
│   ├── Notein/                stale 123-note subset, ignored
│   └── CS Degree/
│       └── Year N/MODULE/
│           ├── Lecture-Slides/    user-managed PDFs (exists for FM2, IAS), read-only to the tool
│           ├── Lecture Notes/     generated PDFs
│           ├── LGT/               generated PDFs
│           ├── SGT/               generated PDFs
│           ├── Flashcards/        generated by Claude sessions
│           └── Practice Exams/    generated by Claude sessions
└── notes-cli/                 this repo
```

The data root is a config value (default `../data` relative to the repo is
not assumed; store an absolute path in a user config file, overridable by
`--data` / `NOTES_DATA`).

Modules: Year 1 — PRG, DBA, DSA, IST, CA1, ELC, FM1. Year 2 — SWE, IAS, FM2,
PAR. This list lives in config.

## What a Notein backup looks like (verified)

- rclone remote `my-drive:` (Google Drive, `drive.readonly` scope). Top
  level: `Notein/`, `NoteInDataSync/`, `Getting started`.
- Every entry in `NoteInDataSync` is a zip named `<title>_<uuid>` with no
  extension. Three kinds:
  - **Note**: contains `note_meta.json` (`id`, `title`, `parentId`,
    `lastModificationTime`, `totalPagesCount`, `inTrashBin`) and a SQLite file
    `note_database_note_<id>_db` plus `-wal`/`-shm` files.
  - **Folder**: contains `folder_<title>` (JSON with `id`, `title`,
    `parentId`) and `folder_labels.json`.
  - **Template**: `template_*`. Ignored.
- Following `parentId` gives the app's folder tree, e.g.
  `Uni CS/Year 1/Semester 2/DBA/DBA LGT Notes`. SWE has no semester level
  (`Uni CS/Year 2/SWE/SWE LGT`). Folder titles can have trailing spaces.
- Note database: `NoteContentEntity.page_list` (ordered page ids),
  `PageEntity` (`paper_spec` JSON with size, `paper_theme` JSON with
  background colour, orientation), `StrokeEntity.record_json` (colour as
  Android ARGB int, `width`, `points` with `x`, `y`, pressure `p`),
  `ShapeEntity` (`points`, `type`, `color`, `width`), `TextBoxEntity`,
  `ImageEntity`, `PageLayerEntity` (`visible`).
- In the one note inspected, A4 `paper_spec` says width 1240 but stroke and
  shape coordinates span roughly 0–595. The coordinate scale must be
  established by the builder, not assumed.

## Commands

| Command | Behaviour |
|---|---|
| `notes sync` | `rclone copy my-drive:NoteInDataSync <data>/NoteInDataSync`, streaming rclone's output. One-way, never deletes. |
| `notes organise` | Read every entry, rebuild the folder tree, print the mapping (note → destination, or skipped + reason) and create the destination folders. Writes no PDFs. |
| `notes convert [MODULE]` | For each mapped note, write `<destination>/<note title>.pdf`. Skip notes whose `lastModificationTime` matches the manifest and whose PDF exists. `--force` re-renders. |
| `notes all` | sync → organise → convert. |
| `notes flashcards MODULE [--week N]` | Prepare the flashcard prompt for that module and launch `claude` in the module folder. |
| `notes exam MODULE [--mcq PCT] [--questions N]` | Prepare the exam prompt and template and launch `claude` in the module folder. |
| `notes exam validate\|merge\|stats MODULE [N\|all]` | The user's old `merge_exam.py`, pointed at `MODULE/Practice Exams/`, with the question-count minimum read from the exam header instead of hardcoded 20. |

### Mapping rule

A note is mapped when its folder path is
`Uni CS/Year N/[Semester M/]MODULE/SUBFOLDER` with MODULE in the config list.
SUBFOLDER, after stripping the module prefix and whitespace, decides the
destination:

| Notein subfolder | Destination |
|---|---|
| `Lecture`, `Lecture Notes`, `Slides` | `Lecture Notes` |
| `LGT`, `LGT Notes` | `LGT` |
| `SGT`, `SGT Notes` | `SGT` (includes the lab notes filed there) |
| anything else, or a note directly in the module folder | skipped |

The `Revision` subtree is skipped because `Revision` is not a module. Notes in
the trash are skipped. The table is config so the user can extend it.

PDF file names are the Notein title, stripped, with characters unsafe for
file names replaced. If two notes map to the same path, both get a short id
suffix. A manifest (JSON, in the data root) records note id → output path and
modification time so renamed or moved notes don't leave orphan PDFs
unreported; orphans are reported, not deleted.

### Converter

One PDF page per Notein page, in `page_list` order, at the page's paper size
and orientation, with the paper background colour. Draw visible layers only.
Strokes are drawn with their colour, opacity and pressure-varying width;
shapes and text boxes are drawn; images are drawn if their data is in the
zip, otherwise skipped with a warning. Output is vector, not rasterised.

Notes written on top of an imported PDF: 88 of the 423 note zips bundle that
PDF as `note_pdf_*.pdf` (46 of them in mapped folders, e.g. half of DSA
Lecture Notes and all of FM1 Slides). `usingOwnPdf` is true on every note and
does not discriminate; the presence of the file does. When the PDF is
bundled, the ink is composited on top of the original pages (designer's
call; this implies PyMuPDF and working out the page and coordinate mapping).
When a note references a PDF that is not bundled, it converts as ink on a
blank page, with a warning.

### Flashcards session

The CLI writes a prompt file into `MODULE/Flashcards/` and launches
`claude "<short instruction to read and follow that file>"` with the module
folder as working directory. The prompt (shipped in the package, filled in
with real paths) tells Claude to:

1. Use all sources for the module (or the given week): `Lecture-Slides`,
   `Lecture Notes`, `LGT`, `SGT`. Slides are read as text; handwritten PDFs
   are read as page images.
2. Work one week at a time, one subagent per week, so the main session stays
   small.
3. First write a topic checklist from every source; then write cards against
   it.
4. Exclude content marked non-examinable. Include every point from "Extra
   Notes" and "Review" sections.
5. Have a second, fresh subagent review the cards against the sources and
   report missing topics and unnecessary cards. Fill the gaps. List proposed
   removals for the user instead of deleting.
6. Write `Flashcards/<MODULE> Week NN.txt`: tab-separated, with Anki header
   lines (`#separator:tab`, `#html:true`, `#notetype:Basic`,
   `#deck:CS Degree::<MODULE>::Week NN`, and column declarations for a GUID
   column and a tags column). Columns: id, front, back, tags. Maths uses
   `\( \)` and `\[ \]`. Ids are stable across regenerations of the same card.

Card identity (designer's call): if the week's file already exists, Claude
reads it first and merges. A card covering the same fact keeps its existing
id even if reworded; only new cards get new ids. The file is never
regenerated from scratch over an existing one.

`--week N` filters sources by a best-effort week number parsed from titles
(`W3`, `Week 3`, `week3`, `lgt4`, `S1W2`, `Week 03`). Files with no
detectable week are passed to Claude in a separate "unassigned" list. For
slides, the week of the containing folder wins over the file name
(designer's call): in FM2, `Week 5 Slides-…/` holds `week7_*.pdf`, and the
folder reflects how the user filed them.

### Exam session

Same launch mechanism. The prompt is the user's existing exam CLAUDE.md
(pasted in the conversation of 2026-11-14) with these changes:

- Sources: `Lecture-Slides` is the primary source; handwritten `Lecture
  Notes`/`LGT`/`SGT` PDFs are a secondary source for extra content. Optional
  `TextBook/` and `MockExamReference/` folders inside the module folder keep
  their old meaning.
- Output goes to `MODULE/Practice Exams/`, with `concept_matrix.md` and
  `exam_template.md` alongside.
- The "two conversations" strategy becomes one session with one subagent per
  batch of five exams; the concept matrix file is the hand-off.
- Tool list and `/workspace` paths removed. Handwritten PDFs are read as
  images, not with `pdftotext`/`tesseract`. The `tiktoken` check is dropped.
- Validation calls `notes exam validate MODULE all` and `notes exam stats
  MODULE`. The old checks assumed an all-MCQ, code-heavy exam and would fail
  every exam for a theory module or a part-written format. Designer's call:
  "Select" labels and the 40% multi-answer rule are checked against the MCQ
  questions only (count taken from the exam header); the 20% code rule
  counts code blocks or maths notation and is a warning, not a failure.
- Source text: the prompt, `exam_template.md` and `merge_exam.py` as pasted
  by the user. Copies believed identical exist at
  `/home/user/Documents/ClaudePrompts/ExamGenerator/`; copy from there only
  with the user's go-ahead.
- Setup questions: module name comes from the command. `--mcq` (percentage of
  multiple choice) and `--questions` (questions per exam) pre-answer two of
  them; anything not supplied is still asked by Claude before generating.
- All question, distractor, answer-key-audit, explanation and checklist rules
  are kept verbatim.

## Approaches considered

1. **Sort by file name suffix** (the original request). Rejected: titles
   follow at least five patterns (`DBA LGT W1`, `FM2 W1 LGT`, `SWE S1W2
   DevOps`, `4ABC1DSA_Lecture_Notes_Week_1_…`, `Lab_2`), so a parser would
   misfile or drop notes.
2. **Sort by the Notein folder each note records** — chosen. Every note
   already sits in a correctly named folder, and the tree is recoverable from
   the backup.
3. **Generate flashcards through the Claude API from inside the CLI.**
   Rejected: needs an API key and per-page cost; launching the user's own
   `claude` session reuses their login and lets them steer.
4. **Anki `.apkg` output.** Rejected in favour of tab-separated text: it is
   what the user's old prompt produced, is human-editable, and needs no
   library. A GUID column gives the same update-on-reimport behaviour.

## Decided by the user

- One Python CLI containing everything; code in `notes-cli/`, data in
  `data/`, both under `NoteinNotes/`.
- `rclone copy`, one-way.
- Anki, tab-separated, decks nested `CS Degree::MODULE::Week N`, with card
  ids.
- Sort by Notein folder; labs go to SGT; PDFs keep Notein titles.
- Flashcards and exams run in a launched Claude session with a default
  prompt.
- Exams focus on lecture content; handwritten notes are secondary.
- The listed changes to the exam prompt and improvements to the flashcard
  prompt.

## Calls made by the designer (correct if wrong)

- `organise` creates folders and reports the mapping only; `.in` files are
  not copied into `CS Degree`. Only PDFs land there.
- CA1 and ELC get empty `Lecture Notes` folders (no lecture notes exist in
  Notein for them); `FM1 Slides` counts as FM1 lecture notes.
- Prompts are written to a file in the module folder and referenced from a
  short launch prompt, instead of being passed whole on the command line.
- `notes exam`/`notes flashcards` replace the current process with `claude`
  (interactive), they do not run headless.

## Left to the builder

- **Survey first.** Before writing the renderer, scan all 423 notes for which
  entity tables are non-empty, which stroke `type` and shape `type` values
  occur, and how coordinates relate to `paper_spec`. Design the renderer for
  what is actually there.
- **Verify by looking.** Render sample notes to PNG (`pdftoppm` is installed)
  and view them. Compare against the page thumbnails where the backup
  includes them (`folder_tn_*` are folder thumbnails; check whether note
  zips carry page thumbnails). A converter that only passes unit tests is not
  done.
- Reading the SQLite database out of the zip safely (it ships with `-wal` and
  `-shm` files; extract all three to a temp dir and open read-only).
- PDF library (reportlab or PyMuPDF), CLI library (argparse or Typer), config
  file format and location.
- Packaging so `uv tool install` puts `notes` on the PATH. Python 3.12.
- Tests (pytest) for: tree reconstruction and mapping, name collisions,
  incremental skip, week parsing, Anki file header, exam validation.
