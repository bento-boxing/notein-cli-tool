# `notes` CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **Execution method (set by the user):** one fresh subagent per task, model `opus` (Opus 5.5), effort `high`, with a fresh reviewer after each task.

**Goal:** A Python CLI, `notes`, that copies a Notein backup from Google Drive, files lecture/LGT/SGT notes into a per-module tree as PDFs, and launches Claude Code sessions that produce Anki flashcards and practice exams.

**Architecture:** A read-only scanner turns the backup's zip entries into a folder tree; a mapper assigns each note a destination; a loader reads each note's SQLite database into plain dataclasses; a renderer draws those to vector PDF with PyMuPDF. Flashcards and exams are not generated by the tool: it writes a prompt file into the module folder and replaces itself with `claude`.

**Tech Stack:** Python 3.12, `argparse`, `tomllib`, `sqlite3`, `zipfile` (all stdlib), PyMuPDF (`pymupdf`) for PDF, `pytest`. External programs: `rclone`, `claude`, `pdftoppm` (verification only).

**Spec:** `docs/superpowers/specs/2026-11-14-notes-cli-design.md` — read it before starting any task.

## Facts established by survey (2026-11-14, all 423 notes)

- Coordinates are in `paper_spec` pixels at 150 dpi: A4 is `1240 × 1754`. Points = pixels × `72/150`. Ink can overshoot the page edge slightly (seen up to x=1408 on a 1240 page); clip, don't rescale.
- Paper specs seen: `A4 1240×1754` (3037 pages, 11 `HORIZONTAL`), `PDF` with various sizes (`1240×1753`, `1315×1754 HORIZONTAL`, `1240×1604`, `1240×1984`, `986×1754 HORIZONTAL`), `Custom 1240×1754`, and `无界` (unbounded) `1920×1920` in 2 notes whose ink reaches 3455×3823. Whether `HORIZONTAL` means width/height are swapped is **not established**.
- Strokes come in two encodings, never both on one row:
  - `record_json` (439,638 strokes, 156 notes): `{type, color, width, points:[{x,y,p,action}], bounds, layerId}`. Only `type: 1` occurs.
  - `ink_stroke_blob` (391,918 strokes, 198 notes, app version ≥ ~381): uncompressed protobuf. **Format solved and verified (2026-11-14):** every one of the 391,918 blobs has the same field sequence, and decoding as below reproduces the row's `left/top/right/bottom` for all of them (0 mismatches at tolerance `width/2 + width + 2 px`); FM2 W1 page 1 and IAS W2 page 2 were rendered and are fully legible.
    - 1 = id (string), 2 = layer id (string), 3 = creation time (varint)
    - 4 = width (fixed32 float, e.g. 2.62)
    - 5 = colour (varint; ~~take the low 32 bits as ARGB~~ **corrected in Task 5:** an Android ColorLong, ARGB in the *high* 32 bits; the low 32 bits are 0 in every blob. See `docs/inkblob-format.md`)
    - 6, 9 = fixed32 floats (unused), 7 = brush name (always `notein-ballpoint-v1`), 8 = varint (unused)
    - 10 = packed little-endian float32 `x,y` pairs (raw, untransformed)
    - 11 = packed float32, 5 per point: elapsed ms, then pressure-like values (second value is the best pressure candidate; unverified, and pressure is not rendered)
    - 12, 13 = 3×3 float32 matrices, row-major. **Page position = M13 · M12 · (x, y, 1).** Typically M12 is scale 1.414 and M13 is scale 0.707 plus a y translation; no rotation or skew occurs anywhere in the backup, but apply the full matrix.
    - 14 = 16 bytes, unused.
  - These are the notes that matter most: **all FM2, IAS, PAR and SWE notes are blob-only** (FM2 60,668 strokes, IAS 46,594), and FM2 and IAS are the modules the user is actively revising.
- `ShapeEntity`: only `type 7, style 0` with 2 points (straight line). 302 notes.
- `ImageEntity`: 52 notes. `uri` ends `…/<image-id>.png`; the zip holds `note_image_<image-id>.png`. `bounds` is JSON `{left,top,right,bottom}`; there is a `rotation` column.
- `TextBoxEntity`: 2 notes. `text` is HTML (`<div><font style="font-size:30px;color:#000000">…`), `bounds` JSON.
- Imported PDFs: 88 notes bundle `note_pdf_<name>.pdf`. Such pages have `paper_theme.type` ending `PdfPaperTheme` with `pageNum` (0-based) and `pdfInfo.pdfPath` whose basename matches the zip entry after `note_pdf_`. 461 pages.
- Layers: every note has `paper_theme` and `default`, both visible. 75 notes have no strokes at all.
- No page thumbnails are bundled. `data/Notein/*/*.in` holds older exports of 123 of the same notes and may contain `record_json` versions of strokes that are blob-only in `NoteInDataSync` (match by stroke `id`), which would give ground truth for the blob decoder.

## Review Focus

1. **A corrupt or half-downloaded zip in `NoteInDataSync`** → reported as a bad entry with its file name; the run continues. (Test in Task 2.)
2. **Titles with `/`, leading dots, trailing spaces, or two notes with the same title in one destination** → safe distinct file names, both written. (Tests in Task 3.)
3. **A note with pages but no ink, or a stroke with a single point** → a valid PDF with blank pages; a dot is drawn as a dot. (Tests in Task 6.)
4. **`notes convert dba` / an unknown module name** → module names are case-insensitive; unknown names exit 2 with the list of valid modules. (Test in Task 1.)
5. **`rclone` or `claude` not on PATH** → exit 1 with a one-line message naming the missing program, no traceback. (Tests in Tasks 8 and 9.)

### Task 6: PDF renderer

**Files:** Create `src/notes_cli/render.py`, `tests/test_render.py`

**Interfaces:**
- Consumes: `Note`, `Page`, `Stroke`, `Line`, `Image`, `TextBox`.
- Produces: `PX_TO_PT = 72 / 150`; `def render_pdf(note: Note, out: Path) -> None` — writes to `out.with_suffix(".pdf.tmp")` then renames, so an interrupted run never leaves a half-written PDF.

Decisions: vector output with PyMuPDF. One PDF page per `Page`, size `width × height × PX_TO_PT`. Background: filled rectangle of `background` colour (white if `None` and no PDF). Each stroke is one polyline with round caps and joins, constant width `stroke.width × PX_TO_PT`, colour and opacity from the ARGB int. Pressure is not used for width in this version (829k strokes; per-segment widths multiply file size and time) — revisit only if Task 8's visual check shows handwriting that is hard to read. A one-point stroke is a filled circle of that diameter. Draw order: background, images, lines and strokes, text boxes. Content outside the page is clipped by the page, not scaled.
